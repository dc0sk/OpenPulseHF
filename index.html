Abstract

What OpenPulseHF is

OpenPulseHF is a software-defined data modem and messaging stack for HF (shortwave) radio. It turns an ordinary SSB transceiver and a computer sound interface into a digital link that, on HF, can span hundreds to thousands of kilometres — without any intervening infrastructure. At its core is an adaptive modem that measures the channel and steps its speed and modulation up or down a single 14-rung ladder to keep the link alive as propagation changes. Messages are protected by forward error correction on every rung and automatic retransmission; station identities by Ed25519 signatures, with an experimental post-quantum option.

The first release (Release 1, v0.17.0) is deliberately narrow: the ladder, session compression, the background daemon and CLI, and an ARDOP-compatible TNC for Pat (Winlink). The much larger rest of the workspace ships disabled or experimental.

Status

Where the project is now

A multi-crate Rust workspace whose first release is deliberately narrow: one adaptive rate ladder with FEC on every rung, session compression, the daemon and CLI, and an ARDOP-compatible TNC for Pat. The rest of the stack — KISS/AX.25, Winlink B2F and the CMS gateway, QSY, mesh, relay, repeater, JS8 discovery, file transfer, the post-quantum handshake, GPU kernels and the GUIs — is in the code but ships disabled or experimental. All tests run against a deterministic loopback backend — no audio hardware is required to build or test.

Why OpenPulseHF

Notable capabilities

Only the first three are part of Release 1. The others are implemented and tested in simulation, but ship disabled or experimental.

One adaptive ladder, coded on every rung

hpx_hf, SL1–SL14: MFSK16 → coded BPSK → differential QPSK250-D → OFDM52 up to 64QAM with high-rate LDPC (r≈8/9), ~9 bps to 7.7 kbps. ACK/NACK- and SNR-driven. Part of Release 1.

LLR-accumulating ARQ

Soft LLR values accumulate across retransmissions (PACTOR-style Memory-ARQ), turning each retry into a soft combining gain. Part of Release 1.

CE-SSB conditioning for data modes

Controlled-Envelope SSB (Hershberger W9GR, QEX 2014) — a voice-SSB technique — applied as a per-mode TX conditioner on the QPSK-subcarrier OFDM modes (OFDM52 on the ladder; the denser OFDM and all SC-FDMA modes are excluded). +1.18 dB average power measured on air at fixed PEP (FT-991A, 2 m). Part of Release 1, default on.

experimentalPost-quantum handshake

ML-DSA-44 + ML-KEM-768 in the ConReq/ConAck frames; Hybrid mode signs with both Ed25519 and ML-DSA-44. Not part of Release 1.

experimentalSC-FDMA on HF

DFT-spread OFDM with DFT-CE pilot channel estimation and MMSE equalisation. The frequency-interleaved pilots limit the realised PAPR advantage; OFDM, not SC-FDMA, is the high-throughput path. Not part of Release 1.

experimentalPilot-framed single carrier

PILOT-* modes up to DVB-S2 32APSK: known in-band pilots drive carrier tracking instead of a decision-directed loop. Not part of Release 1.

experimentalGPU-accelerated DSP

wgpu compute kernels (BPSK modulate/demodulate, timing search, RRC FIR matched filter, 256-pt FFT, soft LLR demod) with automatic CPU fallback, behind the gpu feature. Not part of Release 1.

experimentalEd25519-signed QSY frequency agility

A signed QSY_REQ/LIST/VOTE/ACK protocol, verified against the handshake peer, with initiator and responder in the daemon and rig CAT via rigctld. Not part of Release 1.

experimentalRelay, mesh, repeater

Trust-weighted multi-hop relay with query propagation, mesh re-broadcast with authenticated beacons, and a cross-band repeater. Not part of Release 1.

experimentalJS8-based discovery + rendezvous

A native JS8 waveform (8-GFSK, LDPC(174,87)) to find OpenPulse stations on the JS8 calling frequency, marked by an @OPULSE hint, and negotiate a working frequency. Off by default; RX-only until the operator opts into TX. Not part of Release 1.

experimentalSigned P2P file transfer

Offer/accept transfer with an inline signed TransferManifest + SHA-256 checked against the peer's handshake key; a failed check quarantines the file. Not part of Release 1.

experimentalFreeDV authentication

Ed25519-signed beacons for FreeDV voice via the FreeDV GUI's UDP data port (openpulse-freedv-auth) — no FreeDV fork. Not part of Release 1.

On-air status: a first rig-to-rig decode on 2 m passed on 28 July 2026 (phase A1, on the pre-v0.17 format), and the CE-SSB power and spectrum checks were made on real RF. The Release 1 on-air campaign (M3) has not run yet. Fade performance on HF is validated in the Watterson simulator only.

Modulation modes

The hpx_hf ladder, ~9 bps to 7.7 kbps

Release 1 has one rate ladder, SL1–SL14, with forward error correction on every rung. An adaptive session walks it up and down, driven by ACK/NACK feedback and per-level SNR gates. Adaptive operation is opt-in: [modem] ota_enabled = true on the daemon (default fixed mode BPSK250), [ardop] enable_adaptive_arq = true on the ARDOP TNC.

The BPSK rungs carry RS(255,223), upgraded per frame to RS(255,191) where that costs no extra RS block. ACKs go out on FSK4-ACK (fsk4, 300 Hz) or, when the receiver recommends SL1, on the MFSK16 return channel. These are registered and selectable as fixed modes ([modem] mode), but are not on the Release 1 ladder and carry no release gate; openpulse modes prints the live registry. At 2000 baud use the -RRC variants: plain rectangular QPSK2000 is registered but RRC-superseded, and 8PSK2000 is no longer advertised (#1359), because the crossfade pulse is ISI-limited at 4 samples/symbol. The 9600-baud QPSK9600-RRC / 8PSK9600-RRC waveforms keep their code but are not advertised: they need ≥ 38.4 kHz audio and the engine runs at 8 kHz (post-1.0).

The full rationale for the ladder, its FEC choices and its floors is in docs/mode-fec-ladder.md.

Quick start

Build it, test it — no radio needed

The test suite runs entirely against a deterministic loopback backend. No audio hardware, radio or station is required to build or test.

# Toolchain preflight (required: rustc >= 1.97.1)
./scripts/check-toolchain.sh

# Build (requires libasound2-dev on Linux for the CPAL audio feature)
cargo build --workspace

# Test suite — no audio hardware required
cargo test --workspace --no-default-features

# Lint
cargo clippy --workspace --no-default-features --all-targets -- -D warnings
cargo fmt --all -- --check

# Workspace gate (quote results only from its GATE: line)
scripts/gate.sh

# Benchmark regression gate
cargo run -p openpulse-cli --no-default-features -- --backend loopback --log error benchmark run

# Automated mode × channel test matrix (outputs to docs/test-reports/)
cargo run -p openpulse-testmatrix --no-default-features

Try it without a radio

A purely rig-less demo to get a first impression of the GUIs and the adaptive modem. None of it needs a radio or sound card, and none of it transmits.

# Two-station ARQ link simulator GUI — simulates BOTH stations over a virtual
# HF channel. Change SNR / channel model / mode live and watch the ladder adapt.
cargo run -p openpulse-linksim --features gui --bin openpulse-linksim-gui

# With the operator panel: --serve makes the simulator speak the daemon control
# protocol. Press Run in the simulator, then Connect in the panel (default 127.0.0.1:9000).
cargo run -p openpulse-linksim --features "gui,serve" --bin openpulse-linksim-gui -- --serve 127.0.0.1:9000
cargo run -p openpulse-panel   # in another terminal

For on-air operation, build the daemon or TNC with audio (--features cpal on openpulse-daemon and openpulse-ardop; the CLI has it by default) plus the PTT feature your backend needs (serial for RTS/DTR, gpio), and configure ~/.config/openpulse/config.toml — see the example config, the operator manual and the on-air test plan.

Interoperability

Talking to other software

OpenPulseHF is GPL v3, but these interfaces let non-GPL software interoperate without GPL obligations — each sits behind a process or network protocol boundary. Note that plugins which statically link openpulse-core are derivative works and must be GPL-compatible; the only supported path for a proprietary DSP backend is a separate process bridged over one of these interfaces.
