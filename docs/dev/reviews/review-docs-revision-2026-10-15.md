# Review: documentation revision against the code (2026-10-15)

Adversarial review of commits `27104c2a` ("docs: revise README, user docs and living dev docs against the code") and `662a617e` ("docs: revise the OpenPulseHF book against the code") on top of `7a100654`. The review was read-only: no file other than this one was written, nothing was committed, no cargo build ran, and nothing reached hardware or the network. Every claim below was checked by grep or read against `crates/`, `plugins/`, `apps/`, `scripts/`, the git history (`git cat-file`/`git show` at `v0.16.0`) and the project's own records (`docs/dev/project/workplan.md`, `docs/dev/project/traceability.md`).

## Prompt

Scope: the design-class part of `git diff 7a100654..HEAD` (`docs/dev/design/**`, `docs/dev/hpx-session-state-machine.md`, `docs/dev/onair-execution-plan.md`), with README.md, docs/overview.md, docs/mode-fec-ladder.md and docs/releasenotes.md spot-checked for the same claims. Falsify what the revision adds or changes: wire-format statements (preambles per rung, whitener, binary handshake, station-id cap, ACK reserved bits, the no-interop-with-v0.16.0 claim); the `hpx_hf` ladder numbers and the `fast`/`robust` claims; architecture claims (crates, binaries, data flow, PTT, receive chain); the on-air plan (stations, stage order, runner safety); and contradictions between docs in the same diff. State whether any finding blocks Release 1.

## Verdict

**No finding blocks Release 1.** Release 1 is gated on two stations built from the same commit; none of the errors below changes what the code does, what the on-air evidence must show, or which commit both ends run. The errors are documentation errors that would mislead a reader of the user-facing docs about one wire byte and about two safety behaviours.

Findings: **1 must-fix, 3 should-fix, 3 nits** (one of the nits is in a code comment, not a doc).

## Findings

| # | Finding | Class |
|---|---|---|
| 1 | **The user-facing docs give the wrong handshake version byte, and the design docs in the same diff give the right one.** `README.md:70-71` ("the handshake became a binary format, version 0x02"), `docs/releasenotes.md:31` ("binary, version `0x02`; `0x01` is rejected"), `docs/openpulse-manual.md:30` ("binary v0x02") and `docs/dev/project/changelog.md:29-30` are all lines this diff added. Code: `crates/openpulse-core/src/handshake_wire.rs:53` `pub const WIRE_VERSION: u8 = 0x01;`, with the comment at lines 37-38 saying the "0x01 is rejected" wording became false when the byte was reset, and `split_frame` rejecting anything `!= WIRE_VERSION` (lines 271-275, 352-356). The diff's own `docs/dev/design/architecture.md` corrects the container diagrams to `VERSION(0x01)` and adds "`VERSION` is `WIRE_VERSION` `0x01`, frozen until 1.0"; `docs/dev/design/ladder-versioning.md` (same diff) says "`WIRE_VERSION` `0x01`, frozen until 1.0"; `docs/dev/design/protocol-wire-spec.md:183-186, 275` records the reset (#1204) explicitly. A third party implementing from the README or release notes would send `0x02` and be rejected by every build. | must-fix |
| 2 | **Two sizes for the classical CONREQ in one diff.** `docs/dev/project/changelog.md:30` (added): "A classical CONREQ fits one SAR fragment (241 B, was 710 B in three fragments)". The spec and the code say the *maximal* legal CONREQ is 236 B (`docs/dev/design/protocol-wire-spec.md:174`; `crates/openpulse-core/src/handshake_wire.rs:429-430`, a test that fails if the maximum moves) and that v1 was ~752 B (`protocol-wire-spec.md:176`; `architecture.md` in this diff: "v1's JSON frames were ~752 B and took three"). A 241 B classical CONREQ cannot exist under the caps. | should-fix |
| 3 | **PTT build failure is described as one behaviour; the code has two.** `docs/dev/design/architecture.md`, *Radio interface architecture* (added): "a configured backend that cannot be built stops the daemon at start instead of transmitting into an unkeyed rig". Code: only `PttError::Config` (unknown backend name, feature not compiled) refuses to start (`crates/openpulse-daemon/src/server.rs:2405-2410`, and the start-up check at `server.rs:612-635`); a real backend that is merely unreachable (rig off, port absent) starts the daemon with a `RetryingPtt` that refuses every emission until it reconnects (`server.rs:2411-2425`, `crates/openpulse-radio/src/ptt_builder.rs:250`). The sentence as written tells an operator the daemon will not start when the rig is off; it will, and it will refuse to key. The same paragraph's "refusing emission" behaviour is what the prompt names and is the part the doc leaves out. | should-fix |
| 4 | **The `*_TEST_MODE_EXPECT` guard is attributed to both runners; one runner has it.** `docs/dev/onair-execution-plan.md`, change item 9 (added): "`run-onair-twin-ota.sh` and `run-onair-ic9700-ft991a.sh` only ever **lower** … Mode is per station, and `keep` sends none (the run then requires the expected mode reading, `*_TEST_MODE_EXPECT`, or stops before keying). Both refuse a frequency outside …". `scripts/run-onair-twin-ota.sh:40-43, 90-94` implements `keep` plus the `*_TEST_MODE_EXPECT` stop. `scripts/run-onair-ic9700-ft991a.sh:52, 553-561` honours `keep` (sends no mode) but has no `TEST_MODE_EXPECT` variable or check at all (`grep -n TEST_MODE_EXPECT scripts/run-onair-ic9700-ft991a.sh` finds nothing), so on that runner `keep` keys without confirming the rig's mode. The power and band-limit sentences hold for both scripts. | should-fix |
| 5 | **The v0.16.0 whitener break is cited to the wrong change.** `README.md:70`, `docs/overview.md:54-55`, `docs/mode-fec-ladder.md:258`, `docs/releasenotes.md:29`, and `docs/dev/onair-execution-plan.md` item 2 ("the earlier whitener (#1148)") attribute the whitener break against v0.16.0 to #1148. The v0.16.0 tag (`6a7b9d48`, 2026-07-18) has no scrambler: `git cat-file -e v0.16.0:crates/openpulse-core/src/scramble.rs` reports absent and `git show v0.16.0:crates/openpulse-modem/src/engine.rs` has zero `whiten` hits. The whitener arrived in #1027 (`ac2da26b`, 2026-07-29); #1148 (2026-08-21) replaced its 21-bit keystream with PRBS9 (`protocol-wire-spec.md:118-121`). The conclusion — no rung interoperates — is correct and is actually stronger (v0.16.0 un-whitened frames fail against any post-#1027 build); only the citation is to the second change. | nit |
| 6 | **"Only the benchmark harness and tests" raise the HPX timeout/quality events — one more emitter exists.** `docs/dev/hpx-session-state-machine.md` status note (added): "no production path raises `discovery_timeout`, `training_timeout`, `quality_drop`, `recovery_*` or any relay event; only the benchmark harness and tests do." `apps/openpulse-linksim/src/serve.rs:386-400` emits synthetic `QualityDrop` → `RecoveryOk` transitions for a dropped simulated frame. It is a simulator, not an RF path, so the substance holds; the enumeration is incomplete. | nit |
| 7 | **Stale code comment that probably seeded finding 1.** `crates/openpulse-core/src/handshake_wire.rs:335-336` (doc comment on `split_frame`): "A v1 (`0x01`) frame is rejected here by version" — false since #1204 reset `WIRE_VERSION` to `0x01` (line 53), as the constant's own comment at lines 37-38 says. Not in the diff; recorded because a docs pass "against the code" will keep re-importing it until it is fixed. | nit |

Filters that found nothing, stated as such: `grep -rn "relay_route_failed\|RelayRouteFailed" crates/openpulse-core/src/hpx.rs` found nothing (the doc's "without `relay_route_failed`" is correct; the same grep matches `RelayRouteFound` at line 34, so the filter works). `grep -rln "NoiseHandshake\|NoiseTransport\|openpulse_linksec" crates/openpulse-cli/src` found nothing (the doc's "the CLI's daemon client has no Noise path" is correct; the same filter matches `apps/openpulse-panel/src/transport.rs`). `grep -n "9600" plugins/qpsk/src/lib.rs` within the `supported_modes` list found nothing (the doc's "no longer advertised since #1359" is correct; the string appears only in test fixtures at lines 424 and 443).
